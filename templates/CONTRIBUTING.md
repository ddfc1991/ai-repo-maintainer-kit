# Contributing

Thanks for helping improve this project.

## Before opening a PR

1. Open or find an issue describing the change.
2. Keep the PR focused on one problem.
3. Add or update tests for behavior changes.
4. Update docs when user-facing behavior changes.

## Local setup

```bash
git clone <repo-url>
cd <repo>
# install project dependencies here
```

## PR checklist

- [ ] The change has a clear reason.
- [ ] Tests pass locally.
- [ ] Docs or examples are updated.
- [ ] The PR description explains risk and rollback.

## Review expectations

Maintainers prioritize small, tested, well-explained PRs.
